## 1. โปรแกรมนี้ทำอะไร

ผู้ใช้มีพอร์ตหุ้นอยู่แล้ว เช่น AAPL 60%, MSFT 30%, GOOGL 10% โปรแกรมรับพอร์ตจาก CSV แล้วใช้ราคาย้อนหลังเพื่อวิเคราะห์ว่าหุ้นในพอร์ตเคลื่อนไหวร่วมกันอย่างไร จากนั้นค้นหาหุ้นนอกพอร์ตและทดลองเพิ่มหุ้นหนึ่งตัวในสัดส่วนต่าง ๆ เพื่อดูว่าลดความผันผวนที่ประมาณจากข้อมูลอดีตได้หรือไม่

เมื่อเลือกพอร์ตแล้ว โปรแกรมจะนำไปทดลองกับข้อมูลช่วงถัดมา เปรียบเทียบกับพอร์ตเดิมและพอร์ตแบ่งเงินเท่ากัน พร้อมคิดค่าธรรมเนียมสมมติและสร้างกราฟกับรายงาน

**เป้าหมายที่โค้ดปัจจุบันใช้เลือกพอร์ตคือ ลดความแปรปรวนใน Train เท่านั้น** ยังไม่ได้เลือกโดยชั่งน้ำหนักผลตอบแทนกับความเสี่ยง และไม่ได้รับประกันว่าจะกำไรมากขึ้นหรือขาดทุนน้อยลงทุกช่วง

ภาพรวม:

```text
CSV พอร์ต + CSV ราคาย้อนหลัง
          ↓
ตรวจข้อมูล → แปลงราคาเป็นผลตอบแทน → แบ่ง Train / Test ตามเวลา
          ↓
ใช้ Train: ค่าเฉลี่ย → Centering → Covariance → ความเสี่ยงพอร์ต
          ↓
PCA → เวกเตอร์หุ้นและพอร์ต → คัดหุ้นนอกพอร์ต 10 ตัว
          ↓
ทดลองเพิ่มทีละตัว ที่ 5%, 10%, 15%, 20%
          ↓
เลือกทางเลือกที่มีความแปรปรวน Train ต่ำสุด โดยมีพอร์ตเดิมเป็นตัวเลือก
          ↓
ล็อกพอร์ต → ประเมิน Test → เปรียบเทียบพอร์ตแบ่งเท่ากันและค่าธรรมเนียม
          ↓
คำนวณ Drawdown → สร้างกราฟ → บันทึกรายงาน
```

## 3. รู้จักข้อมูลและสัญลักษณ์ก่อนอ่าน

ตัวอย่างพอร์ต:

```csv
ticker,weight_percent
AAPL,60
MSFT,30
GOOGL,10
```

| สัญลักษณ์ | ความหมาย | ตัวอย่างขนาด |
|---|---|---|
| T | จำนวนวันผลตอบแทนที่ใช้วิเคราะห์ | Train รอบตัวอย่างมี 1,002 วัน |
| N | จำนวนหุ้นในชุดที่กำลังวิเคราะห์ | พอร์ตเริ่มต้นมี 3 หุ้น |
| w | เวกเตอร์น้ำหนักหุ้นในรูปทศนิยม | [0.60, 0.30, 0.10] |
| r_t | เวกเตอร์ผลตอบแทนหุ้นทุกตัวในวัน t | มี N ค่า |
| R | เมทริกซ์ผลตอบแทน แถวเป็นวัน คอลัมน์เป็นหุ้น | T × N |
| mu | ค่าเฉลี่ยผลตอบแทนของหุ้นแต่ละตัว | มี N ค่า |
| X | เมทริกซ์ผลตอบแทนหลังลบค่าเฉลี่ยแต่ละคอลัมน์ | T × N |
| C | Covariance Matrix | N × N |
| Q_k | Eigenvector ที่เลือก k คอลัมน์ | N × k |
| Z | คะแนน PCA ของแต่ละวัน | T × k |
| L | เวกเตอร์ Stock Loadings เรียงเป็นแถวหุ้น | N × k |

ในเอกสารใช้ C แทน covariance เพื่อไม่สับสนกับสัญลักษณ์ใน SVD ส่วน `^T` หมายถึง Transpose และ `@` หมายถึงการคูณเมทริกซ์/เวกเตอร์ ไม่ใช่คูณแต่ละช่อง

**หน่วยสำคัญ:** 1% ต้องเก็บเป็น 0.01 ตอนคำนวณ และน้ำหนัก 60% ต้องเก็บเป็น 0.60 การนำ 1 ไปแทนผลตอบแทน 1% จะทำให้ผลผิดไปมาก

## 4. ขั้นตอนทั้งหมดตามหมายเลขใน main.py

### ขั้น 1–7: รับ CSV ตรวจความถูกต้อง และสร้างเวกเตอร์พอร์ต

1. **รับชื่อไฟล์หรือพาธ:** ผู้ใช้พิมพ์ใน Terminal ตอนรันได้ กด Enter ใช้ portfolio.csv ที่อยู่ข้าง main.py หากส่งเพียงชื่อไฟล์จะค้นในโฟลเดอร์นั้น
2. **อ่าน CSV:** ใช้หัวคอลัมน์จับชื่อข้อมูลของแต่ละแถว
3. **แสดงสิ่งที่อ่านได้:** ชื่อคอลัมน์ จำนวนแถว และข้อมูล เพื่อให้ตรวจว่าเปิดถูกไฟล์
4. **ตรวจคอลัมน์:** ต้องมี ticker และ weight_percent
5. **ตรวจแต่ละรายการ:** ชื่อหุ้นต้องไม่ว่างหรือซ้ำ น้ำหนักต้องเป็นตัวเลขที่มีค่าจำกัด มากกว่า 0 และไม่เกิน 100 พร้อมตัดช่องว่างและปรับชื่อหุ้นเป็นตัวใหญ่
6. **ตรวจผลรวม:** น้ำหนักต้องรวมเป็น 100% โดยยอมรับความคลาดเคลื่อนทศนิยมเล็กน้อย
7. **สร้างเวกเตอร์:** เปลี่ยนเปอร์เซ็นต์เป็นทศนิยมและเก็บคู่รายชื่อหุ้นกับน้ำหนัก

ตัวอย่างผลลัพธ์:

```text
tickers = [AAPL, MSFT, GOOGL]
w       = [0.60, 0.30, 0.10]
```

ตำแหน่งต้องตรงกันตลอดโปรแกรม: น้ำหนักตัวแรกต้องคูณผลตอบแทน AAPL ไม่ใช่ MSFT

**ทฤษฎีที่ใช้:** การแทนข้อมูลด้วยเวกเตอร์ และการคูณด้วยสเกลาร์เพื่อแปลงหน่วย

### ขั้น 8–10: เลือกแหล่งข้อมูลและสร้างเมทริกซ์ผลตอบแทน

มีสองโหมด:

- **โหมด 1 ราคาจริง:** อ่าน CSV ของ stockdata ผ่าน price_data.py แล้วคำนวณผลตอบแทนเอง
- **โหมด 2 ตัวอย่างสมมติ:** อ่านผลตอบแทนที่เตรียมไว้ เพื่อดู Dot Product หนึ่งวันและเมทริกซ์หลายวัน เหมาะกับตรวจสูตร ไม่ได้ทำกระบวนการค้นหุ้นและ Test จริงครบทุกขั้น

CSV ราคาจริงต้องมีอย่างน้อย Date, Ticker, Close ส่วนไฟล์จาก stockdata มีคอลัมน์ราคาอื่นและ Volume ด้วย แต่กระบวนการนี้ใช้ Close

สูตร:

```text
ผลตอบแทน = ราคาวันปัจจุบัน / ราคาวันก่อนหน้า - 1
ตัวอย่าง ราคา 100 → 102
ผลตอบแทน = 102 / 100 - 1 = 0.02 = 2%
```

โปรแกรมจัดข้อมูลเป็น:

```text
                 AAPL     MSFT     GOOGL
วัน 1             0.01    -0.005     0.02
วัน 2            -0.01     0.01     -0.02
วัน 3             0.005    0         0.015
```

แต่ละแถวคือ **หนึ่งเวกเตอร์ข้อมูลของหนึ่งวัน** การมี Train 1,002 แถวจึงเกินเงื่อนไข 150 เวกเตอร์ของงาน ไม่ต้องนับจำนวนหุ้นให้ถึง 150 เพื่อผ่านเงื่อนไขนี้

การตรวจข้อมูลราคาปัจจุบัน:

- วันต้องอ่านได้ ชื่อหุ้นต้องมี และต้องพบหุ้นที่ผู้ใช้ถือในไฟล์ราคา
- ราคาที่ใช้ต้องเป็นบวกและเป็นตัวเลขที่มีค่าจำกัด ราคาซ้ำของหุ้นเดิมในวันเดียวกันทำให้หยุดตรวจสอบ
- หากคู่วันใดมีราคาหุ้นในพอร์ตไม่ครบ จะไม่ใช้ผลตอบแทนคู่นั้น ไม่เติมราคาเองและไม่เชื่อมข้ามวันที่ขาดแล้วเรียกว่าเป็นผลตอบแทนหนึ่งวัน
- ไม่ลบผลตอบแทนสูง/ต่ำทิ้งโดยอัตโนมัติ และไม่แก้ไฟล์ราคาต้นฉบับ
- ปฏิทินวันมาจาก CSV ถ้าทุกหุ้นหายไปทั้งวัน ระบบยังตรวจวันนั้นไม่ได้ด้วยปฏิทินตลาดภายนอก

บันทึกรายละเอียดลง last_price_audit.json

**ทฤษฎีที่ใช้:** เวกเตอร์ผลตอบแทน เมทริกซ์ข้อมูล และการจัดลำดับพิกัด

### ขั้น 10.1: แบ่ง Train และ Test ตามเวลา

เปรียบเหมือนฝึกทำโจทย์จากอดีต แล้วปิดคำตอบก่อนสอบด้วยช่วงถัดมา

- **Train:** ใช้หาค่าเฉลี่ย covariance, PCA, คัดหุ้น และเลือกสัดส่วน
- **Test:** ใช้ประเมินพอร์ตที่เลือกเสร็จแล้ว ห้ามย้อนกลับมาเลือกหุ้นจากผล Test

แบ่งประมาณ 80/20 ตามปฏิทินข้อมูลก่อนกรองวันขาดหาย ไม่สุ่มสลับวัน เพื่อรักษาลำดับอดีตไปอนาคต

รอบตัวอย่าง:

| ส่วน | ช่วงวันผลตอบแทน | จำนวน |
|---|---|---:|
| Train | 2021-10-15 ถึง 2025-10-13 | 1,002 วัน |
| Test | 2025-10-14 ถึง 2026-10-13 | 251 วัน |

บันทึกขอบเขตลง last_split_summary.json ตั้งแต่ขั้น 11 เป็นต้นไป การสร้างแบบจำลองใช้ Train

**เรื่องที่ใช้:** การประเมินข้อมูลอนุกรมเวลาและการป้องกันข้อมูลอนาคตรั่วเข้าแบบจำลอง ไม่ใช่ทฤษฎีเมทริกซ์โดยตรง

### ขั้น 11: คำนวณผลตอบแทนพอร์ตด้วย Dot Product

เอาน้ำหนักแต่ละหุ้นคูณผลตอบแทนหุ้นนั้น แล้วรวมกัน

```text
w = [0.60, 0.30, 0.10]
r = [0.01, -0.005, 0.02]
ผลตอบแทนพอร์ต = 0.60×0.01 + 0.30×(-0.005) + 0.10×0.02
              = 0.0065 = 0.65%
```

ทำพร้อมกันทุกวันได้ด้วย `R @ w` ได้เวกเตอร์ผลตอบแทนพอร์ต T ค่า

**สมมติฐาน:** ส่วนนี้ใช้น้ำหนักชุดเดิมกับทุกวันเพื่อวิเคราะห์ความเสี่ยง ต่างจาก Test ที่ซื้อแล้วถือและปล่อยให้น้ำหนักเปลี่ยนตามราคา

**ทฤษฎีที่ใช้:** Dot Product, ผลรวมเชิงเส้น และเมทริกซ์คูณเวกเตอร์

### ขั้น 12–14: หาค่าเฉลี่ยและทำ Centering

12. หาค่าเฉลี่ยผลตอบแทนของหุ้นแต่ละคอลัมน์ ได้เวกเตอร์ mu
13. ลบค่าเฉลี่ยของหุ้นนั้นออกจากผลตอบแทนทุกวัน ได้ X
14. ตรวจว่าค่าเฉลี่ยแต่ละคอลัมน์ของ X ใกล้ 0

ตัวอย่างสมมติหุ้นหนึ่งตัวให้ผลตอบแทน 1%, 2%, 3% ค่าเฉลี่ยคือ 2%:

```text
ก่อน Centering:  [ 1%, 2%, 3% ]
ลบค่าเฉลี่ย 2%: [-1%, 0%, 1% ]
ค่าเฉลี่ยใหม่ = (-1 + 0 + 1) / 3 = 0%
```

**ไม่ได้ทำให้ทุกค่ากลายเป็นศูนย์** แต่ทำให้จุดกึ่งกลางของข้อมูลอยู่ที่ศูนย์ จึงเห็นว่าแต่ละวันสูงหรือต่ำกว่าปกติของหุ้นตัวเองเท่าไร คอมพิวเตอร์อาจแสดง -0.000000 หรือเศษเล็กมากจากการคำนวณทศนิยม

โค้ดนี้ทำ Centering แต่ไม่ได้หารด้วยส่วนเบี่ยงเบนมาตรฐานเพื่อทำ Standardization ก่อน PCA

**ทฤษฎีที่ใช้:** ค่าเฉลี่ย การลบเวกเตอร์ และการเลื่อนจุดศูนย์กลางข้อมูล

### ขั้น 15–16: คำนวณ Covariance Matrix

15. แสดงตัวอย่าง covariance ของหุ้นคู่แรกเพื่อให้คำนวณตามได้
16. ทำกับหุ้นทุกคู่ รวมทั้งหุ้นกับตัวเอง ได้เมทริกซ์ C

```text
C = (X^T @ X) / (T - 1)
```

แต่ละช่องคือผลรวมของการคูณค่าหลัง Centering ของหุ้นสองตัวในวันเดียวกัน หารด้วย T−1 ตามสูตร sample covariance

ตัวอย่างสมมติหลัง Centering:

```text
หุ้น A = [-0.01, 0, 0.01]
หุ้น B = [-0.02, 0, 0.02]
Cov(A,B) = [(-0.01)(-0.02) + 0 + (0.01)(0.02)] / 2
         = 0.0002
```

- ค่าบวก: มีแนวโน้มเบี่ยงเบนจากค่าเฉลี่ยไปทางเดียวกัน
- ค่าลบ: มีแนวโน้มเบี่ยงเบนสวนกัน
- ค่าใกล้ศูนย์: ความสัมพันธ์เชิงเส้นลักษณะนี้น้อย ไม่ได้แปลว่าไม่มีความสัมพันธ์ทุกรูปแบบ
- ช่องแนวทแยงคือ variance ของหุ้นแต่ละตัว

C เป็นเมทริกซ์สมมาตร เพราะ Cov(A,B) = Cov(B,A) และเป็น positive semidefinite ในทางคณิตศาสตร์

**ทฤษฎีที่ใช้:** Transpose, การคูณเมทริกซ์, Dot Product, เมทริกซ์สมมาตร และ covariance

### ขั้น 17–18: คำนวณความผันผวนและ Correlation

17. ถอดราก variance บนแนวทแยง ได้ส่วนเบี่ยงเบนมาตรฐานหรือ SD ของหุ้นแต่ละตัว
18. ปรับ covariance ด้วย SD เพื่อให้เปรียบเทียบความสัมพันธ์ได้ในช่วง -1 ถึง 1

```text
SD_i = sqrt(C[i,i])
Correlation(i,j) = C[i,j] / (SD_i × SD_j)
```

หากหุ้นไม่มีความผันผวน SD = 0 สูตร correlation จะหารศูนย์ โปรแกรมแสดงว่าไม่มีนิยาม ไม่ตีความเป็น correlation เท่ากับศูนย์

**ทฤษฎีที่ใช้:** Variance, SD และ correlation ข้อมูลนี้ช่วยอ่านความสัมพันธ์ แต่ correlation ต่ำอย่างเดียวไม่พอจะเลือกพอร์ต

### ขั้น 19–20: คำนวณความเสี่ยงพอร์ตและตรวจสูตรสองทาง

19. ใช้ทั้งน้ำหนักและ covariance ทุกคู่:

```text
ความแปรปรวนพอร์ต = w^T @ C @ w
ความผันผวนพอร์ต = sqrt(ความแปรปรวนพอร์ต)
```

20. คำนวณ sample variance จากผลตอบแทนพอร์ตในขั้น 11 แล้วตรวจว่าตรงกับขั้น 19 ภายในความคลาดเคลื่อนเล็กน้อย

สำหรับสองหุ้น สูตรขยายคือ:

```text
variance = w1²×C11 + w2²×C22 + 2×w1×w2×C12
```

จึงเห็นว่าความเสี่ยงพอร์ตขึ้นกับทั้งความเสี่ยงรายตัว สัดส่วนลงทุน และการเคลื่อนไหวร่วมกัน ไม่ใช่เฉลี่ย SD ของหุ้นตรง ๆ

**ทฤษฎีที่ใช้:** Quadratic Form, เมทริกซ์คูณเวกเตอร์ และ Dot Product

### ขั้น 21–23: ทำ PCA เพื่อหาแกนความผันผวนหลัก

21. ใช้ `numpy.linalg.eigh(C)` หา eigenvalue และ eigenvector ของ C แล้วเรียงตาม eigenvalue จากมากไปน้อย
22. หาสัดส่วนความแปรปรวนที่แต่ละแกนอธิบายได้ และเลือกจำนวนแกนน้อยที่สุดที่ยอดสะสมถึงเป้าหมาย
23. ฉายข้อมูลแต่ละวันลงบนแกนที่เลือก ได้คะแนน PCA หรือ Z

```text
C @ q_i = lambda_i × q_i
สัดส่วนแกน i = lambda_i / ผลรวม eigenvalue ทุกตัว
Z = X @ Q_k
```

ให้คิดว่าหุ้นหลายร้อยตัวเคลื่อนไหวร่วมกันบางแบบ PCA สร้างแกนใหม่เพื่อสรุปรูปแบบความผันผวนเหล่านั้น แกนที่เก็บไว้ช่วยแทนข้อมูลโดยใช้จำนวนพิกัดน้อยลง

**ค่าที่ใช้อยู่จริงใน main.py คือ pca_target = 0.95 หรือ 95%** แม้คอมเมนต์เก่าบรรทัดหนึ่งยังเขียน 80% ตัวเลข 95% หมายถึงสัดส่วนความแปรปรวนที่เก็บ ไม่ใช่ความแม่นยำทำนาย 95% และไม่ใช่โอกาสกำไร

จำนวนแกนเป็นจำนวนเต็ม จึงเป็นไปได้ที่เปลี่ยนเป้าหมายเล็กน้อยแล้วได้จำนวนแกนเท่าเดิม หากยังอยู่ระหว่างยอดสะสมสองค่าเดิม

Eigenvector เลือกให้ตั้งฉากกันได้ และคะแนนองค์ประกอบหลักต่างแกนมี covariance เป็นศูนย์บนข้อมูลที่ใช้สร้าง PCA แต่ไม่ได้แปลว่าเป็นอิสระทางสถิติทุกรูปแบบ หรือรู้ว่าแกนนั้นคือดอกเบี้ย/เศรษฐกิจโดยอัตโนมัติ

**ทฤษฎีที่ใช้:** Eigenvalue, Eigenvector, Orthogonality, ฐานและมิติ, Projection และ PCA

### ขั้น 24–26: สร้างเวกเตอร์หุ้นบนแกน PCA และเทียบกับพอร์ต

24. สร้าง L โดยนำแต่ละคอลัมน์ eigenvector ที่เลือกคูณราก eigenvalue ของแกนนั้น
25. รวมเวกเตอร์หุ้นตามน้ำหนักเดิมเป็นเวกเตอร์พอร์ต
26. ใช้ cosine similarity วัดทิศทางเวกเตอร์หุ้นเทียบกับเวกเตอร์พอร์ต พร้อมแสดง correlation จากข้อมูลเต็มประกอบ

```text
L = Q_k @ diag(sqrt(lambda_1), ..., sqrt(lambda_k))
เวกเตอร์พอร์ตบนแกน PCA = w^T @ L
cosine(a,b) = dot(a,b) / (norm(a) × norm(b))
```

**แยกสองอย่างนี้ให้ชัด:**

- Z ในขั้น 23: หนึ่งแถวแทน “หนึ่งวัน”
- L ในขั้น 24: หนึ่งแถวแทน “หนึ่งหุ้น”

เราใช้แถวของ L เปรียบเทียบหุ้น ไม่เอาคะแนนรายวันมาเข้าใจว่าเป็นเวกเตอร์หุ้น และ eigenvector ไม่ใช่สัดส่วนลงทุนที่แนะนำ

ในนิยาม L นี้ `L @ L^T` ประมาณ covariance ด้วยแกนที่เก็บไว้ ถ้าเก็บแกนครบ การวัด cosine ระหว่างเวกเตอร์หุ้นกับเวกเตอร์พอร์ตจะตรงกับ correlation เมื่อทั้งคู่มีความแปรปรวนไม่เป็นศูนย์ แต่เมื่อเก็บบางแกนเป็นเพียงค่าประมาณ

**ทฤษฎีที่ใช้:** Linear Combination, Norm, Dot Product, มุมระหว่างเวกเตอร์ และการแยกองค์ประกอบของ covariance

```text

ค่าธรรมเนียม = 0.001 × 0.40 = 0.0004 = 0.04% ของเงินพอร์ต
```

เป็นต้นทุนประมาณการจากน้ำหนักเป้าหมาย ยังไม่แก้การจัดสรรเงินหลังค่าธรรมเนียมแบบละเอียด พอร์ตเดิมไม่เสียค่าปรับพอร์ตนี้ ไม่คิดต้นทุนใหม่ทุกวันและไม่คิดขายปิดพอร์ตตอนจบ ผลตอบแทนวันแรกของ Test รวมต้นทุนเริ่มต้น จึงกระทบทั้ง NAV และ SD หลังต้นทุนด้วย

ไฟล์ผลลัพธ์: cost_comparison.csv, cost_daily.csv, cost_weights.csv และ cost_assumptions.json

**ทฤษฎีที่ใช้:** ผลต่างเวกเตอร์ ค่าสัมบูรณ์และผลรวม หรือ L1 norm ของการเปลี่ยนน้ำหนัก รวมถึงการประเมิน baseline

### ขั้น 38–40: Drawdown กราฟ และรายงาน

ส่วนนี้ทำใน report_charts.py

38. คำนวณ Drawdown ของ NAV หลังต้นทุน และหา Maximum Drawdown
39. สร้างกราฟมูลค่าพอร์ต กราฟ Drawdown และกราฟเปรียบเทียบตัวชี้วัด
40. บันทึกผลที่ reports/latest ชุดเดียว เมื่อรันพอร์ตใหม่สำเร็จให้เขียนทับรายงานและไฟล์ประกอบ พร้อมล้างผลเก่าที่รอบใหม่ไม่ได้ใช้

```text
ยอดสูงสุดถึงวันนี้ = ค่าสูงสุดของ NAV ตั้งแต่เริ่มจนถึงวันนี้
Drawdown (%) = (NAV วันนี้ / ยอดสูงสุดถึงวันนี้ - 1) × 100
Maximum Drawdown = ค่า Drawdown ที่ติดลบมากที่สุด
```

ตัวอย่าง NAV: 100 → 120 → 96

```text
วันที่ NAV = 96 ลดจากยอด 120 ไป 20%
Drawdown = (96 / 120 - 1) × 100 = -20%
```

Drawdown วัดการลดจากยอดก่อนหน้า จึงต่างจาก SD ที่วัดการกระจายของผลตอบแทนรายวัน พอร์ต SD ต่ำกว่าไม่จำเป็นต้องมี Maximum Drawdown ดีกว่า

## 7. ข้อจำกัดที่สมาชิกกลุ่มควรรู้

1. ระบบอ่าน CSV ย้อนหลัง ไม่ใช่ระบบ real-time และไม่ได้ส่งคำสั่งซื้อขายจริง
2. เลือกพอร์ตด้วยความแปรปรวน Train เพียงอย่างเดียว ความผันผวนรวมทั้งการแกว่งด้านบวกและลบ ไม่ใช่ความเสี่ยงขาดทุนเพียงด้านเดียว
3. ค้นเฉพาะ shortlist และสัดส่วนที่กำหนด ไม่ใช่หุ้นที่ดีที่สุดหรือสัดส่วนที่ดีที่สุดจากทุกทางเลือก
4. PCA ใช้ covariance หลัง Centering ไม่ใช่ข้อมูลที่ปรับ SD ของหุ้นทุกตัวให้เท่ากัน หุ้นที่ผันผวนมากจึงมีผลต่อแกนหลักได้มาก
5. สูตรความเสี่ยง Train ใช้น้ำหนักคงที่ แต่ Test ใช้ Buy and Hold น้ำหนักจึงเปลี่ยนไปตามราคา
6. การใช้รายชื่อสมาชิกดัชนีปัจจุบันย้อนหลังอาจมี survivorship bias ไม่ได้จำลองสมาชิกดัชนีจริงในทุกวันอดีต
7. การเตรียมราคาจาก stockdata ตั้ง auto_adjust=True การจำลองใช้การเติบโตของราคาที่ปรับแล้ว ไม่ได้จำลองกระแสเงินสดปันผล ภาษี อัตราแลกเปลี่ยน หรือราคาที่ซื้อขายสำเร็จจริงอย่างละเอียด
8. ค่าธรรมเนียมเป็นสมมติฐาน และยังไม่รวม slippage หรือค่าขายปิดพอร์ตปลายช่วง
9. ผลมาจาก Train/Test ชุดเดียว หากใช้ผล Test นี้ปรับวิธีแล้ว ต้องมีการประเมินกับช่วงที่ยังไม่ได้ใช้เลือกวิธีด้วย ไม่ควรปรับจนชนะชุดเดิมแล้วอ้างว่าใช้ได้ทั่วไป

## 11. ขั้น 41–43: ทางเลือกความผันผวน 1–3 ระดับและสิ่งที่ต้องแลก

ไฟล์ risk_levels.py เพิ่มการสรุปหลายระดับโดยใช้ฟังก์ชันคำนวณความเสี่ยงและ Test เดิม

41. เลือกหุ้นที่ variance Train ต่ำสุดของแต่ละสัดส่วนเพิ่มหุ้น 5%, 10%, 15%, 20% ก่อน เก็บเฉพาะทางเลือกที่ variance ต่ำกว่าพอร์ตเดิม แล้วเรียง SD จากต่ำไปสูงและตัดระดับที่ซ้ำ ถ้ามีเกินสามระดับเลือกต่ำสุด ใกล้กึ่งกลางช่วง SD และสูงสุด หากมีน้อยกว่าสามแสดงตามจริง หากไม่มีคงพอร์ตเดิม
42. ล็อกระดับเหล่านั้นแล้วคำนวณ Test หลังค่าธรรมเนียม แสดงผลตอบแทนและ SD ก่อน → หลัง เทียบพอร์ตเดิม รวม Equal Weight และ Maximum Drawdown ลำดับระดับหมายถึง Train ไม่รับประกันว่าลำดับ Test จะเหมือนกัน คำว่า “สูง” หมายถึงสูงกว่าในกลุ่มทางเลือก ไม่ใช่ระดับความเสี่ยงมาตรฐาน
43. แปลงผลเป็นข้อความอ่านง่ายและจำนวนเงินบนเงินเริ่มต้นสมมติ 100,000 หน่วยเงิน บันทึก risk_levels.md, risk_levels.csv, risk_level_weights.csv ในโฟลเดอร์รายงานรอบนั้น และแนบตารางไว้ท้าย report.md

สูตรแสดงผล:

- SD ลดลงสัมพัทธ์ (%) = (SD เดิม − SD ใหม่) / SD เดิม × 100; ค่าติดลบหมายถึง SD เพิ่ม
- ผลตอบแทนต่าง (จุดเปอร์เซ็นต์) = ผลตอบแทนใหม่ (%) − ผลตอบแทนเดิม (%)
- กำไรเปลี่ยนสัมพัทธ์ (%) = (ผลตอบแทนใหม่ − ผลตอบแทนเดิม) / ผลตอบแทนเดิม × 100 ใช้เมื่อเดิมเป็นบวกและใหม่ไม่ติดลบ
- หากทั้งคู่ขาดทุน บอกว่าขาดทุนเพิ่มหรือลดเทียบขนาดขาดทุนเดิม หากข้ามจากกำไรเป็นขาดทุนบอกการเปลี่ยนฝั่ง หากฐานใกล้ศูนย์ไม่หารเพื่อสร้างเปอร์เซ็นต์สัมพัทธ์
- กำไร/ขาดทุนเป็นเงิน = เงินเริ่มต้น × ผลตอบแทนสุทธิ (%) / 100
- ขนาด 1 SD เป็นเงิน = เงินเริ่มต้น × SD รายวัน (%) / 100 ไม่ใช่ขาดทุนต่อวัน เพดานขาดทุน หรือเงินที่ประหยัดได้

ทุกระดับยังเลือกด้วย variance Train เท่านั้น ไม่ได้เพิ่มตัวทำนายผลตอบแทนหรือ Indicator และไม่เลือกสัดส่วนใหม่หลังดู Test กราฟเดิมใน report.md ยังเปรียบเทียบพอร์ตเดิมกับตัวเลือก Train ต่ำสุดและ Equal Weight; ตารางท้ายรายงานแสดงทุกระดับ

รันเหมือนเดิมด้วย python main.py และอ่านขั้น 41–43 ท้าย Terminal หรือเปิด risk_levels.md ในรายงานรอบนั้น ทดสอบสูตรและกรณีพิเศษด้วย python -m unittest test_risk_levels.py การรัน compare_example_portfolios.py จะสร้างตารางหลายระดับให้ทุกพอร์ตตัวอย่างในโฟลเดอร์ผลของรอบนั้นด้วย


## 12. ขั้น 44: ความกระจุกตัวและด่านตรวจความคุ้มค่า

ใช้ S&P 500 และข้อมูลเดิม เพิ่ม recommendation.py และ recommendation_policy.json โดยไม่เปลี่ยน CSV พอร์ตผู้ใช้ สูตรวิเคราะห์เดิม และตารางเปรียบเทียบเดิมยังเก็บไว้ แต่แยกออกจากคำแนะนำสุดท้ายอย่างชัดเจน

### ความกระจุกตัว

- หุ้นน้ำหนักมากที่สุดและผลรวมน้ำหนักสามอันดับแรก
- HHI = sum(w_i²) และจำนวนหุ้นเทียบเท่าแบบแบ่งเท่ากัน = 1 / HHI วัดเฉพาะการกระจายน้ำหนัก ไม่ได้บอกจำนวนธุรกิจอิสระ
- Correlation เฉลี่ยของคู่หุ้น ถ่วงด้วย w_i × w_j โดยไม่รวมแนวทแยง และรายชื่อห้าคู่ที่มี correlation สูงสุด ใช้ covariance ของ Train ก่อน Test คู่ที่ SD เป็นศูนย์ไม่นับเป็น correlation ศูนย์ แต่ระบุว่าไม่มีนิยาม

### แยกข้อมูลสำหรับคำแนะนำ

จาก Train เดิมแบ่ง 75% แรกเป็น Fit และ 25% หลังเป็น Validation โดยไม่แตะ Test:

Fit → สร้าง PCA/shortlist/ทดลองน้ำหนัก/เลือกระดับ
Validation → ประเมิน Buy and Hold หลังค่าธรรมเนียมและตรวจทุกเกณฑ์
Test → แสดงผลของทางเลือกที่ผ่านและล็อกแล้ว ไม่เปลี่ยนคำแนะนำจากผล Test

ตัวอย่างข้อมูลปัจจุบัน: Fit 751 วันถึง 2024-10-10; Validation 251 วัน 2024-10-11 ถึง 2025-10-13; Test เดิม 2025-10-14 ถึง 2026-10-13 ไม่มีการ fit ใหม่ด้วย Validation หลังตรวจผ่าน ดังนั้นทางเลือกด่านนี้อาจต่างจากตารางวิเคราะห์เดิมที่ใช้ Train ทั้งช่วง

### เกณฑ์เริ่มต้น

ต้องผ่านพร้อมกันทุกข้อบน Validation:

1. SD รายวันลดอย่างน้อย 5% สัมพัทธ์กับพอร์ตเดิม
2. ผลตอบแทนสุทธิลดไม่เกิน 2 จุดเปอร์เซ็นต์ เช่น 20% เหลือ 18% อยู่ตรงขอบเกณฑ์
3. Maximum Drawdown ต้องไม่แย่ลง เช่น -17% เป็น -18% ไม่ผ่าน แต่ -17% เป็น -15% ผ่านด้านนี้

ค่าเกณฑ์เป็นนโยบายทดลอง ไม่ใช่มาตรฐานทางการเงิน ปรับใน recommendation_policy.json ได้ หลีกเลี่ยงการปรับจนชนะ Test เดิม และต้องใช้ช่วงใหม่ประเมินหากพัฒนาวิธีจากผลที่เห็นแล้ว

Fit ต้องมีอย่างน้อย 150 วัน และ Validation อย่างน้อย 60 วันตามค่าเริ่มต้น หากข้อมูลไม่พอ ไม่สมบูรณ์ หรือไม่มีทางเลือกผ่าน ระบบคงพอร์ตเดิมพร้อมเหตุผล หากผ่านบางระดับ จะแนะนำเฉพาะระดับเหล่านั้น เลขระดับอาจไม่ต่อกันเพราะไม่เปลี่ยนชื่อหลังคัดออก

### ไฟล์ที่อ่าน

- recommendation.md: สรุปสุดท้าย พร้อมความกระจุกตัว เกณฑ์ ช่วงข้อมูล และเหตุผลไม่ผ่านแต่ละระดับ
- recommendation.json: ผลตรวจ เกณฑ์ น้ำหนัก และแหล่งข้อมูลสำหรับตรวจย้อนหลัง
- recommended_weights.csv: เฉพาะน้ำหนักระดับที่ผ่านเกณฑ์ ถ้าคงพอร์ตเดิมจะมีเพียงหัวคอลัมน์ ไม่ได้หมายถึงขายหุ้นทั้งหมด
- approved_test/risk_levels.md และ CSV: ผล Test ของทางเลือกที่ผ่านเท่านั้น ถ้ามีข้อมูล Test ไม่ครบจะแสดงประเมินไม่ได้ ไม่เลือกหุ้นอื่นมาแทน
- report.md: สรุปคำแนะนำอยู่ต้นรายงาน การวิเคราะห์ขั้น 1–43 อยู่ภาคผนวก

proposed_weights.csv และ risk_level_weights.csv เดิมยังเป็นทางเลือกเชิงวิเคราะห์ ไม่ใช่คำแนะนำหลังตรวจความคุ้มค่า ไม่มีส่วนใดส่งคำสั่งซื้อขายหรือแก้ portfolio.csv อัตโนมัติ

ทดสอบด่านความคุ้มค่าและกรณีพิเศษด้วย `python -m unittest test_recommendation.py test_risk_levels.py` จากโฟลเดอร์ longtripletun
